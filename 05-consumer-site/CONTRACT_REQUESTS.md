# Contract requests from 05-consumer-site

1. **Erased-farmer lots (`UNVERIFIABLE`).** `GET /public/provenance/:sscc` returns a `Provenance` with no `status`, so the page cannot tell an erased lot (show "The grower has exercised their right to erase personal data. The handling record is intact; the link to the farm can no longer be verified.") from an ordinary one. The fixture note says live mode may answer `ERR_NOT_FOUND`-like, which would be shown as "We cannot find this lot", the wrong message. Request: add `originVerifiable: boolean` (or `status: LotStatus`) to `Provenance`, and a fixture for an erased lot.
2. **Scan anomaly.** PROMPT.md asks for "scanned in several cities" handling. Nothing in `Provenance` or the API carries that flag. Request: `scanAnomaly?: boolean` on `Provenance`, set from the scan telemetry.
3. **Residue credential reference.** The "How we know" text for the residue check can only say "recorded on the ledger". Request: `residueCredential?: { txId, blockNumber, channel }` (or label the entries in `proofs[]` with the event name) so the check can link to its own entry.
4. **Labelled proofs and endorsers.** `proofs[]` has no event name and no endorsing orgs. The page shows the channel's member organisations (from contract section 7) rather than inventing endorsers. Request: `proofs[].event` and `proofs[].endorsers` (org types) if the page should show who signed each entry.
5. **Bengali place names.** `Provenance.village` and `journey[].place` are English only, so Bengali pages show English place names. Request: `villageBn`, or let the page read `GET /villages` (it has `nameBn`) and map by name.
